Да. И у тебя это выглядит вполне реализуемо.

1. **Может ли локальный Figma plugin ходить в локальный HTTP server?**

Да, может, но не “просто так”, а если это разрешено в `manifest.json` через `networkAccess.allowedDomains`. В документации Figma указано, что для `allowedDomains` допустимы схемы `http`, `https`, `ws`, `wss`, а поддержка `localhost` была отдельно добавлена в обновлении API. ([Figma Developer Docs][1])

У тебя сейчас в `manifest.json` разрешен только `https://cdn.jsdelivr.net`, то есть на `http://localhost:...` текущая версия плагина ходить не должна.

Практически тебе нужно будет добавить что-то вроде:

```json
"networkAccess": {
  "allowedDomains": [
    "https://cdn.jsdelivr.net",
    "http://localhost:3456",
    "ws://localhost:3456"
  ],
  "reasoning": "Load JSZip and talk to local companion server for atlas/ts generation"
}
```

Если нужен дев-режим пошире, Figma также описывает `devAllowedDomains`. ([Figma Developer Docs][1])

Важный нюанс: сетевой доступ — это одно, а **запись файлов прямо из плагина в произвольную папку на диске** — другое. У Figma-плагина нормального прямого доступа к локальной файловой системе как у Node-приложения нет. Поэтому запись в папку игры лучше делать именно через companion server, а не из самого плагина. Это хорошо сочетается с твоей задачей. Текущая архитектура у тебя уже разделена: `code.js` отдает экспорт в UI, а `ui.html` уже делает packing/generation.

2. **Можно ли сделать companion server рядом с плагином и вынести туда упаковку через free-tex-packer-core?**

Да, это как раз нормальный путь.

Сейчас у тебя atlas packing уже реализован прямо в `ui.html` своим MaxRects/shelf-пэкером, без Node-зависимостей. В readme это прямо описано.

Но если хочешь:

* использовать `free-tex-packer-core` из npm,
* писать файлы прямо в папку игры,
* делать watch/live-sync,

то companion server лучше.

Логика будет такая:

* `code.js` как и сейчас экспортирует PNG + manifest из Figma.
* `ui.html` вместо локальной сборки ZIP шлет payload на `http://localhost:3456/export`.
* companion server:

    * принимает `manifest + files`,
    * запускает `free-tex-packer-core`,
    * генерирует `atlas png/json`,
    * генерирует `*-assets.ts`, `*-scene.ts`, `types.ts`, `utils.ts`,
    * пишет все это в указанную папку игры.

Это даже проще сопровождать, чем держать packing в HTML-UI.

3. **Можно ли сделать, чтобы изменения в Figma почти сразу отражались в Phaser?**

Да, но не в виде “плагин сам живет фоном внутри Figma и постоянно следит”. Лучше делать это как **push по кнопке/таймеру из UI + companion server + watch в игре**.

Тут есть 3 уровня реалистичности:

### Вариант A. Самый нормальный

* В Figma-плагине кнопка `Sync to Game`
* По нажатию:

    * экспорт,
    * POST на localhost companion,
    * companion перезаписывает atlas/json/ts в проект игры,
    * Vite/Webpack/ts-node-dev/свой watcher подхватывает изменения,
    * Phaser-сцена перезапускается

Это надежно и просто.

### Вариант B. Полуавтомат

* В UI плагина включается `Auto Sync every N sec`
* Плагин раз в 2–3 секунды повторяет экспорт текущего selection
* шлет результат на localhost
* companion сравнивает hash и пишет файлы только если реально есть изменения

Это уже похоже на “моментально”, но надо аккуратно:

* не спамить exportAsync,
* не писать файлы без изменений,
* не дергать игру лишний раз.

### Вариант C. Почти live

* companion поднимает `ws://localhost:3456`
* плагин держит websocket
* при каждом sync шлет payload
* companion после записи файлов шлет событие в dev-сервер игры
* игра показывает “assets updated” и делает `scene.restart()`

Это лучший DX, если хочется гладко.

Но важное ограничение: **Figma plugin сам по себе не дает тебе настоящего события “любой пиксель в выделении изменился — мгновенно экспортируй” как полноценный live design bridge**. Поэтому обычно делают либо ручной sync, либо polling/interval, либо реакцию на смену selection/document changes настолько, насколько это доступно и стабильно в твоем сценарии. Я бы не строил систему на “магическом полном live”. Лучше честный auto-sync loop.

4. **Что у тебя уже готово для такого перехода**

У тебя уже есть почти вся середина пайплайна:

* `code.js` собирает:

    * PNG верхних детей,
    * координаты,
    * `manifest`,
    * предупреждения по именам,
    * и шлет это в UI как `EXPORT_READY`.
* `ui.html` уже умеет:

    * держать `packName`,
    * `atlasBasePath`,
    * строить atlas,
    * генерировать TS-файлы,
    * собирать ZIP.
* readme уже описывает целевой output для Phaser.

То есть тебе не надо изобретать формат. Надо просто заменить последний шаг:

* **сейчас:** `UI -> ZIP download`
* **нужно:** `UI -> localhost companion -> write into game folder`

5. **Как я бы это сделал минимально**

Структура:

```text
figma-plugin-phaser-view/
  manifest.json
  code.js
  ui.html
  companion/
    package.json
    server.ts
    generate-phaser-files.ts
    write-output.ts
```

Эндпоинты companion:

* `POST /export`

    * принимает `{ packName, atlasBasePath, manifest, files[] }`
* `GET /health`
* `WS /events` опционально

Companion делает:

* decode PNG bytes
* `free-tex-packer-core`
* generate atlas
* generate ts
* write to:

    * `game/src/autogen/phaser/scene/...`
    * `game/public/assets/atlases/...`
      или куда тебе удобно

И еще:

* хранить `gameOutputDir` не в Figma plugin, а в companion config
* например `companion.config.json`

Так безопаснее и проще.

6. **Короткие ответы по твоим пунктам**

**1. Может ли связываться с локальным http server?**
Да, если добавить `localhost`/`http://localhost:port` в `networkAccess.allowedDomains`. Сейчас у тебя это не настроено. ([Figma Developer Docs][1])

**2. Можно ли сделать companion server рядом, который пакует через free-tex-packer-core?**
Да. Это хороший и, на мой взгляд, правильный путь. У тебя уже выделен удобный boundary между export из Figma и дальнейшей генерацией.

**3. Можно ли регулярно перегенерировать ts-файлы и сразу класть в папку игры?**
Да, через companion server — да. Напрямую из плагина в папку игры — плохая идея и обычно не тот уровень доступа. Лучший вариант: плагин шлет payload на localhost, companion пишет файлы, игра через watcher/webpack/vite реагирует и перезапускает сцену. ([Figma Developer Docs][2])

Самое важное: **твоя идея жизнеспособна, и архитектурно ты уже почти у цели**.

* поправить `manifest.json` под localhost,
* вынести из `ui.html` только этап `buildZipArchive` в `POST /export`,
* оставить `code.js` почти как есть.
